# Linux ARM

Android-приложение, которое запускает полноценные Linux-десктопы «в один тап»: без
Termux и Termux:X11, с аппаратным ускорением на Adreno через Turnip (Mesa) поверх KGSL.
APK, образы дистрибутивов и драйверы GPU собираются в GitHub Actions.

Основная цель: Snapdragon 8 Gen 5 / Adreno 829 (OnePlus 15R, Android 16), но подойдёт
любой arm64-телефон с Adreno 6xx–8xx и Android 10+.

> **Версия 0.2.** Встроенный полноэкранный X11 с жестами и прозрачными кнопками, звук,
> автообновление, ярлыки Linux-программ на рабочем столе Android, образы Debian XFCE и
> GNOME (экспериментальный), Turnip из upstream Mesa каждый день.

## Возможности

- **Экран внутри приложения**, полноэкранный, с вырезом камеры. Жесты тремя/четырьмя
  пальцами (тап и свайпы) и прозрачные кнопки поверх рабочего стола: сочетания клавиш,
  команды внутри Linux или действия приложения. Кнопки перетаскиваются и редактируются
  прямо на экране: меню (жест «назад», ☰ или три пальца вверх) → «Настроить кнопки». Все жесты —
  во вкладке «Управление».
- **Ярлыки программ:** меню плитки → «Программы и ярлыки» → значок справа. На рабочем
  столе Android появится ярлык программы из Linux; тап по нему сам запустит дистрибутив
  и программу.
- **Звук:** PulseAudio внутри дистрибутива → Android (48 кГц, стерео).
- **Автообновление:** вкладка «Обновления» раз в минуту проверяет `version.json` в
  релизе, показывает список изменений и ставит новую версию с проверкой sha256.
  Каналы: «Тестовые» (каждый push) и «Стабильные» (теги `v*`).

## Установка

1. Скачайте `linux-arm-latest-debug.apk` из релиза
   [**apk-latest**](../../releases/tag/apk-latest). Этот релиз обновляется после каждого
   push. Стабильные версии публикуются в релизах `v*`.
2. Разрешите приложению работать в фоне: карточка **«Защита от закрытия»** на главном
   экране → «Разрешить» (исключение из оптимизации батареи; без него ColorOS, MIUI и
   One UI закрывают рабочий стол при выключенном экране).

   Ограничение дочерних процессов Android (phantom process killer, не больше 32
   процессов) приложение обходит само, без параметров разработчика: пока сессия
   запущена, оно держит число процессов Linux ниже предела и закрывает фоновые службы,
   которые рабочий стол перезапустит при необходимости (миниатюры, индексатор, монитор
   дисков). Текущее число видно в уведомлении. Чтобы снять ограничение полностью:
   - «Параметры разработчика» → **«Отключить ограничения дочерних процессов»**, или
   - один раз выполнить
     `adb shell pm grant io.github.gl1ch5.linuxarm android.permission.WRITE_SECURE_SETTINGS`
     (с компьютера или через Shizuku). После этого приложение само отключает
     ограничение при каждом запуске, а параметры разработчика можно выключить.
3. Откройте **«Драйверы»** и установите свежий Turnip (`glibc` для Debian, Arch и Fedora,
   `musl` для Alpine).
4. На главном экране нажмите на плитку дистрибутива: первый тап устанавливает его,
   следующие запускают.
5. Чтобы проверить GPU: меню плитки → **«Проверить GPU»** (запускает `vulkaninfo --summary`
   и `glxinfo -B`) или ярлык `vkcube` на рабочем столе XFCE.

Debug- и release-сборки подписаны разными ключами. Чтобы переключиться между ними,
удалите приложение (при этом удалятся и установленные дистрибутивы).

### Если что-то не работает

Откройте вкладку **«Логи» → «Поделиться»**: приложение соберёт zip со всеми логами и
сведениями об устройстве. Файлы логов:

| Файл | Что внутри |
|---|---|
| `app.log` | события приложения: установка, запуск, выбор драйвера, ошибки |
| `session-<id>.log` | вывод рабочего стола внутри proot и проверка Turnip перед стартом |
| `xserver.log` | stdout/stderr X-сервера |
| `logcat.log` | logcat приложения во время сессии (X-сервер, экран, ввод) |
| `diagnostics.log` | результат «Проверить GPU» |

## Как это устроено

```
┌──────────── Приложение (Kotlin, Compose) ────────────┐
│ Плитки / Драйверы / Логи      SessionService (FGS)   │
│        │                         │                   │
│        ▼                         ▼                   │
│  Экран X11 (Termux:X11     процесс :xserver          │
│  MainActivity, ввод)  ◄──► X-сервер (libXlorie)      │
│                              │ /tmp/.X11-unix/X0     │
│                              ▼                       │
│  libproot.so ──► rootfs дистрибутива (Debian, …)     │
│                  DISPLAY=:0, Turnip из /opt/gpu-driver│
└──────────────────────────────────────────────────────┘
                         │ /dev/kgsl-3d0
                         ▼
                      Adreno GPU
```

- **X-сервер:** модуль `lorie` из Termux:X11 (git-подмодуль) работает в отдельном процессе
  приложения `:xserver`. Его сокет создаётся в `rootfs/tmp/.X11-unix`, поэтому внутри
  дистрибутива он находится по обычному пути `/tmp/.X11-unix/X0`. Кадры передаются через
  AHardwareBuffer/DRI3 без копирования. Экран и ввод (тачпад, прямое касание, жесты,
  доп. клавиши) пока полностью берутся из Termux:X11. Частота обновления (60/90/120 Гц)
  задаётся в настройках дистрибутива.
- **proot** (форк Termux) собирается через NDK в `native/proot/build.sh`. Набор bind-mount'ов
  такой же, как в proot-distro, плюс поддельные файлы `/proc`, которые Android скрывает.
- **Драйвер GPU не ставится в дистрибутив:** каждая версия распаковывается в
  `files/drivers/<id>` и через `proot --bind` монтируется в `/opt/gpu-driver` выбранного
  дистрибутива. Приложение само выставляет `VK_ICD_FILENAMES`, `LD_LIBRARY_PATH`,
  `MESA_LOADER_DRIVER_OVERRIDE=zink`, `TU_DEBUG` и остальные переменные. Ручные переменные
  задаются в настройках дистрибутива («Расширенные»).
- **Резервный режим:** перед стартом приложение запускает `vulkaninfo --summary`. Если
  Turnip не инициализировался или нет доступа к `/dev/kgsl-3d0`, сессия стартует на
  llvmpipe и выводит сообщение с причиной.

### Почему proot лежит в `jniLibs` (выбор targetSdk)

Начиная с targetSdk 29, Android запрещает `execve()` файлов из записываемых каталогов
приложения (W^X). Есть два пути: остаться на targetSdk 28, как Termux, или класть
исполняемые файлы в APK как `lib*.so`.

Выбран **второй путь: targetSdk 35**. `proot` и его loader упакованы как `libproot.so` и
`libproot-loader.so`, приложение собирается с `useLegacyPackaging = true`, и установщик
распаковывает их в `nativeLibraryDir`. Это единственный каталог приложения, откуда exec
разрешён. Гостевые программы при этом не запускаются через `execve`: proot отображает их
в память через loader (`PROOT_LOADER`), поэтому запрет на них не распространяется.
targetSdk 28 отклонён: Android 16 помечает такие приложения как устаревшие, и для них
постепенно отключают новые API.

Termux:X11 обычно грузит `libXlorie.so` прямо из APK, что требует несжатых библиотек.
Здесь X-сервер создаётся внутри обычного процесса приложения (сервис `:xserver`), а
библиотека загружается из `nativeLibraryDir`. Это работает без `app_process` и без
скрытых API.

## GPU-драйверы

Workflow `build-turnip.yml` каждый день собирает Mesa из upstream:

- каналы **stable** (последний тег `mesa-X.Y.Z`) и **nightly** (`main`);
- **glibc** (сборка в контейнере Debian 13; подходит для Debian, Arch, Fedora) и **musl**
  (Alpine);
- опции: `-Dfreedreno-kmds=kgsl -Dvulkan-drivers=freedreno -Dgallium-drivers=zink`,
  префикс `/opt/gpu-driver/usr`. Подробности — в `drivers/turnip/build.sh`.

Каждая сборка — отдельный релиз `turnip-<канал>-<версия>` с архивом, `.sha256` и
`manifest.json`. Сводный список лежит в `drivers.json` релиза `turnip-index`, по нему
приложение проверяет обновления. Хранится 10 последних сборок каждого канала.

В приложении можно скачать сборку (sha256 проверяется), держать несколько версий,
выбрать драйвер для каждого дистрибутива и откатиться на предыдущий выбор.

**Импорт сторонних сборок** (zip в формате AdrenoTools или наш `.tar.zst`): большинство
zip-архивов AdrenoTools собраны для Android-эмуляторов под bionic (libc Android) и не
загрузятся в glibc- или musl-дистрибутиве. Приложение проверяет зависимости `.so` и в таком
случае объясняет причину отказа. Подойдёт только сборка Turnip под Linux aarch64 (KGSL).

Своё изменение для Mesa можно добавить через `drivers/turnip/patches/{common,stable,nightly}/*.patch`.

## Образы

`build-images.yml` собирает образы на ARM-раннерах GitHub (нативно, без QEMU). Каждый
образ — это каталог `images/<id>/` с `image.json` (метаданные) и `setup.sh` (выполняется в
arm64-контейнере базового образа). Результат: `<id>.rootfs.tar.zst` и запись в общем
`images.json` в релизе `images`.

| Образ | Статус |
|---|---|
| `debian-xfce`: Debian 13 + XFCE, vkcube/glxinfo | этап 1 |
| Omarchy (Arch Linux ARM + Hyprland, вложенно через Weston) | этап 3 |
| Десктоп в стиле macOS (собственное название, без брендинга Apple) | этап 3 |
| KDE Plasma Mobile (Debian 13, kwin_wayland вложенно в X11, см. `docs/plasma-mobile.md`) | экспериментально |
| GNOME | этап 4, после исследования |
| `debian-phosh`: Debian 13 + Phosh (мобильная оболочка GNOME) во вложенном phoc | экспериментально, см. `docs/phosh.md` |
| `debian-touch`: Debian 13 + Openbox, нижняя панель, сетка приложений и Onboard | мобильный, сенсорный |
| Lomiri (оболочка Ubuntu Touch) | не собран: нужен systemd, см. `docs/lomiri.md` |

## Сборка (CI)

| Workflow | Когда | Что делает |
|---|---|---|
| `build-apk.yml` | каждый push, теги `v*` | debug APK → релиз `apk-latest`; подписанный release APK для тега |
| `build-turnip.yml` | ежедневно, вручную, при изменении `drivers/turnip` | Turnip stable/nightly × glibc/musl |
| `build-images.yml` | вручную, при изменении `images/` | rootfs-образы и `images.json` |

Секреты для release-подписи: `KEYSTORE_BASE64` (keystore в base64), `KEYSTORE_PASSWORD`,
`KEY_ALIAS`, `KEY_PASSWORD`. Debug-сборки подписаны публичным ключом `app/debug.keystore`,
чтобы каждая следующая устанавливалась поверх предыдущей. **Не используйте его для
релизов.**

Для локальной сборки нужны JDK 21, Android SDK (platform 37, NDK 29.0.14206865) и `gawk`:

```sh
git submodule update --init --recursive
native/proot/build.sh
./gradlew :app:assembleDebug
```

## Безопасность

- **proot — не песочница.** Это слой совместимости: процессы дистрибутива работают с
  правами приложения и имеют доступ ко всем его файлам (в том числе к другим
  установленным дистрибутивам). «root» внутри дистрибутива — поддельный.
- Внешняя граница — песочница Android-приложения. Общая папка `/sdcard` выключена по
  умолчанию и включается отдельно для каждого дистрибутива.
- При прямом доступе к GPU через KGSL браузеры на Chromium приходится запускать без их
  собственной песочницы (`--no-sandbox`): внутри proot она не работает. Открывайте в таком
  браузере только сайты, которым доверяете.
- Образы и драйверы скачиваются по HTTPS из релизов этого репозитория, их sha256
  проверяется.
